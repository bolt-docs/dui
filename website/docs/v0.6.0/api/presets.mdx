# Theme presets

Five curated palettes ship in `@bdocs/dui` so a CLI can theme every
widget &mdash; `badge`, `modal`, `tabs`, `box`, `section`, `spinner`,
`progress`, `markdown`, `kbd` &mdash; with **one line** of code:

```ts
import { configure, presets } from "@bdocs/dui";
configure({ theme: presets.dracula });
```

A preset is a `Partial<DuiTheme>` (see [`DuiTheme`](./theme)). Slots
the preset doesn't set fall back to the built-in defaults, so each
palette stays focused on the high-impact surfaces rather than
spelling out every leaf.

```ts
import { presets, type PresetName } from "@bdocs/dui";

const theme: PresetName = "catppuccin";
configure({ theme: presets[theme] });
```

The `PresetName` union means misspelled palettes surface at compile
time, so a typo like `presets.draclua` is caught by `tsc --noEmit`
before reaching CI.

## Available palettes

1. [`dracula`](#dracula) &mdash; [draculatheme.com](https://draculatheme.com).
2. [`nord`](#nord) &mdash; [nordtheme.com](https://www.nordtheme.com).
3. [`solarized`](#solarized) &mdash; [ethanschoonover.com/solarized](http://ethanschoonover.com/solarized).
4. [`catppuccin`](#catppuccin-mocha) &mdash; [catppuccin.com](https://catppuccin.com). Mocha variant.
5. [`gruvbox`](#gruvbox) &mdash; [github.com/morhetz/gruvbox](https://github.com/morhetz/gruvbox). Dark.

The registry is exported as `Readonly<Record<PresetName, DuiThemePreset>>`
and the underlying object is `Object.freeze`d so a caller's accidental
mutation doesn't leak across consumers.

## How cascade works

The presets ride the same `configure({ theme })` pipeline as a
hand-rolled `DuiTheme`. Three layers compose, in order of priority:

1. **User overrides** &mdash; whatever you pass inline wins:
   ```ts
   configure({
     theme: {
       ...presets.dracula,
       error: "#ff00ff", // lock this single slot
     },
   });
   ```
2. **Preset palette** &mdash; the value at `presets.X.<slot>`.
3. **Built-in defaults** &mdash; the hardcoded `map[slot]` inside
   `resolveColor` (`packages/dui/src/theme.ts`), applied last.

Per-slot fallback also kicks in: if `box.title` isn't set on a preset
but the global `title` IS, `box.title` reuses `title`.

## Cascade in widget output

Once applied, every widget picks up the palette through
`resolveColor`:

```ts
configure({ theme: presets.dracula });
const out = badge({ label: "PASS", status: "success" });
// out contains `\u001b[48;2;80;250;123m` (Dracula success bg)
```

The 24-bit RGB SGR opens with `\u001b[48;2;<r>;<g>;<b>m` so a
consumer can grep for the preset's hex by inspecting the raw paint.

## Force plain-text output

`plain: true` is **orthogonal** to presets. Pass it alongside a
palette to keep the diagnostic theme introspection working while
collapsing every render path into the multi-line `prefix:` text
fallback — useful for screen-reader users on Linux, CI log
scrapers, or any host that lacks ANSI-capable rendering:

```ts
configure({ theme: presets.dracula, plain: true });
```

The Dracula palette is still resolved into the theme slot map (so
`getConfig().theme` shows the intended palette), but every widget
emits text-only output. See the full accessibility reference in
[Accessibility](/docs/v0.6.0/overview/accessibility) for the NO_COLOR /
TERM=dumb / screen-reader heuristics.

## Adding your own preset

Append a new entry to `packages/dui/src/presets.ts`:

```ts
import type { DuiThemePreset } from "@bdocs/dui";

const myPreset: DuiThemePreset = {
  success: "#...your hex...",
  error: "#...your hex...",
  /* ... */
};

Object.assign(presets, { myPreset });
// Or extend PresetName and the read-only Record literal up top so
// the change is type-checked from both sides.
```

If the preset name is added in step 1 (`type PresetName = "..."`),
the registry surfaces a compile error wherever a misspelled palette
is referenced &mdash; so the prescription is usually:
1. add `"myPreset"` to `PresetName`,
2. add the palette const + entry in the `Readonly<Record>` literal.

A new palette automatically rides the same `markRawTheme`,
`resolveColor`, and `configure` pipeline. No separate registration
step. Vitest cascade coverage in `tests/presets.test.ts` exercises
both the registry shape and the per-palette widget paint.

## Override a single slot

Don't want to override *everything* the preset sets? Pick a slot:

```ts
// override the success color *only* while keeping the rest of Gruvbox
configure({
  theme: {
    ...presets.gruvbox,
    success: "#b4dc54",
  },
});
```

Or via the per-call `colors:` argument on the widget itself:

```ts
badge({ label: "DRAFT", status: "neutral", colors: { bg: "#bd93f9" } });
```

## Run on a single widget type

If only a subset of widgets should follow the preset (e.g. a single
modal dialog inside an otherwise-default CLI), scope the theme
pass through `box({ colors })`:

```ts
modal({
  title: "Confirm",
  content: "Are you sure?",
  buttons: [
    { label: "Cancel" },
    { label: "Delete", primary: true },
  ],
  colors: {
    border: presets.dracula.accent as string,
    buttonPrimary: {
      fg: "#f8f8f2",
      bg: presets.dracula.accent as string,
    } as never,
  },
});
```
