## createProgressBar

```ts
createProgressBar(opts?: ProgressBarOptions): ProgressBar
```

Creates a standard progress bar. In TTY terminals it renders inline with periodic updates. In non-TTY environments (CI, logs) it writes a new line per update.

### Usage

```ts
const bar = createProgressBar({ width: 30 })

bar.start(100)         // total steps
bar.update(50, 'compiling...')  // current + message
bar.stop('done!')      // finish

console.log(bar.percentage)  // 50
```

## createAnimatedProgressBar <Badge type="warning">next</Badge>

```ts
createAnimatedProgressBar(opts?: AnimatedProgressBarOptions): ProgressBar
```

Creates a progress bar with **smooth-fill animated transitions**. Every `update()` call triggers an `animateProgress()` animation from the bar's current **displayed** position to the new target, using the configured easing and duration.

Rapid successive calls cancel the in-flight animation and start fresh from wherever the bar is currently shown — so the bar always feels responsive, never "jumps" or "lags behind."

On non-TTY terminals (CI, logs, piped output) it falls back to discrete writes, identical to `createProgressBar`.

### Usage

```ts
const bar = createAnimatedProgressBar({
  width: 40,
  prefix: 'deploying',
  // ── animation control (new in v0.7.0) ──
  easing: 'ease-out-cubic',   // deceleration curve — fast start, slow finish
  animDuration: 500,           // 500ms per transition
})

bar.start(5)          // total = 5 steps
bar.update(1)         // smoothly fills to 20%
bar.update(3)         // smoothly fills from ~20% to 60%
bar.update(5)         // smoothly fills from ~60% to 100%
bar.stop('complete')  // snaps to 100% immediately
```

### Easing presets

The `easing` option accepts any value that [`animateProgress()`](./animation) supports:

| Category | Presets |
|----------|---------|
| Standard | `linear`, `ease-in`, `ease-out`, `ease-in-out` |
| Power series | `-quad`, `-cubic`, `-quart`, `-quint` |
| Trigonometric | `-sine` |
| Exponential | `-expo` |
| Circular | `-circ` |
| Overshoot | `-back` |
| Elastic | `-elastic` |
| Bounce | `-bounce` |
| CSS string | `cubic-bezier(0.42, 0, 0.58, 1)` |
| Spring | `{ stiffness: 180, damping: 12 }` |

### Visual comparison

Standard bar (discrete jumps):
```
██████████████░░░░░░  60%
███████████████████  100%     ← jumps from 60→100
```

Animated bar (smooth fill):
```
██████████████░░░░░░  60%     ← update(100) called here
████████████████░░░░  65%     ← first animation frame
██████████████████░░  82%     ← mid-animation
████████████████████  100%    ← animation complete
```

### Options

<Field name="width" type="number" default="30">Width of the bar in characters.</Field>
<Field name="barChar" type="string" default="'█'">Character for the filled portion.</Field>
<Field name="emptyChar" type="string" default="'░'">Character for the remaining portion.</Field>
<Field name="prefix" type="string">Text before the bar.</Field>
<Field name="suffix" type="string">Text after the percentage.</Field>
<Field name="color" type="ColorStyle" default="theme.progress.bar">Color of the filled bar.</Field>

#### Animation options (v0.7.0)

<Field name="easing" type="Easing" default="'ease-out'">Easing function or preset for the smooth-fill animation. Accepts named presets, custom functions, CSS `cubic-bezier()` strings, or spring config objects.</Field>
<Field name="animDuration" type="number" default="300">Duration of each smooth-fill transition in milliseconds. Shorter values feel snappier; longer values let the easing curve show.</Field>

### Behavior notes

- **Rapid updates** — calling `update()` while an animation is still running cancels the in-flight animation and starts fresh from the currently displayed position. The bar never "catches up" in a jarring jump.
- **No-op animation** — position changes smaller than 0.5% skip the animation loop entirely and snap immediately, avoiding wasted timer overhead for trivial nudges.
- **Non-TTY** — falls back to discrete line-per-update writes, same as the standard bar. No animation loop is started on piped output.

## createMultiProgressBar <Badge type="warning">next</Badge>

```ts
createMultiProgressBar(opts: MultiProgressBarOptions): MultiProgressBarHandle
```

Composes multiple animated progress bars in **parallel** — each with its own easing, color, and characters — rendered on stacked terminal rows. Ideal for download managers, parallel build steps (lint + test + build running simultaneously), or server-health dashboards where each metric gets its own animated bar.

### Usage

```ts
const multi = createMultiProgressBar({
  bars: [
    { label: 'download', width: 30, color: 'cyan',  easing: 'ease-out' },
    { label: 'verify',   width: 30, color: 'green', easing: 'ease-out-cubic' },
    { label: 'install',  width: 30, color: 'yellow' },
  ],
  spacing: 1,   // blank row between bars
})

multi.start()

multi.bars[0].update(50, 'fetching...')
multi.bars[1].update(30, 'checksum')
multi.bars[2].update(10)

setTimeout(() => {
  multi.bars[0].update(100, 'complete')
  multi.bars[1].update(100)
  multi.bars[2].update(100, 'done')
  multi.stop('all finished')
}, 3000)
```

verify    ████████████░░░░░░░░░░░░░░░░  30% | checksum

### How it works

Each bar behaves like an independent `createAnimatedProgressBar` with its own easing, duration, color, bar characters, and animation state. When any bar's `update()` is called, it starts its own smooth-fill animation. On every animation frame, **all bars are re-rendered** together on their respective rows — so the group stays visually coherent.

Rapid successive updates on a single bar cancel only that bar's in-flight animation, leaving the others unaffected.

### Example: Parallel build steps

```ts
const multi = createMultiProgressBar({
  bars: [
    { label: '  lint', width: 40, color: '#f59e0b' },
    { label: '  test', width: 40, color: '#ef4444' },
    { label: ' build', width: 40, color: '#22c55e' },
  ],
  spacing: 1,
})

multi.start()

// Simulate concurrent task output
const lint = multi.bars[0]
const test = multi.bars[1]
const build = multi.bars[2]

lint.start(100); test.start(100); build.start(100)

const interval = setInterval(() => {
  lint.update(Math.min(lint.percentage + random(10, 30), 100))
  test.update(Math.min(test.percentage + random(5, 20), 100))
  build.update(Math.min(build.percentage + random(3, 15), 100))

  if (lint.percentage >= 100 && test.percentage >= 100 && build.percentage >= 100) {
    clearInterval(interval)
    multi.stop('all checks passed')
  }
}, 800)
```

### Options

<Field name="bars" type="MultiBarConfig[]">Array of per-bar configurations. Each entry extends `AnimatedProgressBarOptions` with an optional `label` string displayed at the start of the bar line.</Field>
<Field name="spacing" type="number" default="0">Extra blank rows between each bar for visual breathing room.</Field>

#### Per-bar config (MultiBarConfig)

Inherits all [AnimatedProgressBarOptions](#options) plus:

<Field name="label" type="string">Short label displayed at the start of the bar line. Useful when multiple bars represent different tasks (e.g. `"build"`, `"lint"`, `"test"`).</Field>

### MultiProgressBarHandle API

<Field name="start" type="() => void">Start all bars at once — hides cursor, renders initial state (each bar at 0%).</Field>
<Field name="stop" type="(message?: string) => void">Stop all bars, kill in-flight animations, render final state, show cursor.</Field>
<Field name="bars" type="readonly MultiBarHandle[]">Read-only array of per-bar controllers.</Field>

#### Per-bar handle (MultiBarHandle)

| Method | Description |
|--------|-------------|
| `start(total?)` | Set this bar's total. |
| `update(current, msg?)` | Update this bar's progress — triggers its local smooth-fill animation. |
| `stop(msg?)` | Freeze this bar at its current percentage. Other bars continue animating. |
| `percentage` | Current 0–100 progress of this bar (read-only). |
| `index` | Zero-based index within the multi-bar group. |

## task <Badge type="warning">next</Badge>

```ts
task<T>(label: string, optionsOrTotal: TaskOptions | number, fn: (ctx: TaskContext) => Promise<T>): Promise<T>
```

High-level wrapper that runs a promise-returning function with an **auto-managed animated progress bar**. The bar starts as soon as you call `task()`, and automatically finishes (or stops with an error message) when the promise resolves or rejects.

### Usage

```ts
import { task } from '@bdocs/dui'

const result = await task('installing', 3, async (ctx) => {
  await fetchPackage()
  ctx.update(1, 'fetched')      // bar fills to ~33%

  await build()
  ctx.update(2, 'compiled')     // bar fills to ~67%

  await deploy()
  ctx.update(3, 'deployed')     // bar fills to 100%
})
// bar auto-stops: "installing done"
```

### Stages example

```ts
const release = await task('release', { total: 4 }, async (ctx) => {
  ctx.setMessage('linting...')
  await lint()
  ctx.update(1, 'linted')

  ctx.setMessage('testing...')
  await test()
  ctx.update(2, 'tested')

  ctx.setMessage('building...')
  await build()
  ctx.update(3, 'built')

  await publish()
  ctx.update(4, 'published')
})
```

### Error handling

When the work function throws or returns a rejected promise, the bar stops with an error message (default: `"{label} failed"`) and the rejection propagates so you can handle it with `try/catch`:

```ts
try {
  await task('deploy', 2, async (ctx) => {
    ctx.update(1, 'staging')
    throw new Error('connection timeout')
  })
} catch (err) {
  // bar already shows: "deploy failed"
  console.error('Deployment aborted:', err)
}
```

### Options

<Field name="total" type="number" default="1">Total number of steps for the task.</Field>
<Field name="successMessage" type="string" default="`{label} done`">Message shown when the task completes.</Field>
<Field name="errorMessage" type="string" default="`{label} failed`">Message shown when the task fails.</Field>

All [AnimatedProgressBarOptions](#options) (width, barChar, emptyChar, color, easing, animDuration, prefix, suffix) are also accepted and passed through to the underlying bar.

### Shorthand

Pass a number as the second argument to set `total` without an options object:

```ts
await task('download', 5, async (ctx) => { ... })
```

### TaskContext API

| Method | Description |
|--------|-------------|
| `update(current, message?)` | Advance progress to step `current` and optionally update the status message. |
| `setMessage(message)` | Update the status message without changing progress. |
| `percentage` | Current progress as a 0–100 value (read-only). |

## Theming

Use the `progress.bar` theme slot for global styling:

```ts
configure({
  theme: {
    progress: {
      bar: { fg: '#22c55e', bg: '#052e16' },
    },
  },
})
```

Or pass color per-call:

```ts
createProgressBar({
  color: '#ff8800',
})
```

### Custom characters

```ts
createProgressBar({
  width: 20,
  barChar: '#',
  emptyChar: '-',
  color: '#60a5fa',
})
```

## API (shared)

Both `createProgressBar` and `createAnimatedProgressBar` return the same `ProgressBar` interface:

<Field name="start" type="(total?: number) => void">Start the progress bar. Optionally set the total steps.</Field>
<Field name="update" type="(current: number, message?: string) => void">Update the current progress and optional status message.</Field>
<Field name="stop" type="(message?: string) => void">Complete the progress bar and restore the cursor.</Field>
<Field name="percentage" type="number">Current progress as a 0–100 value (read-only).</Field>
