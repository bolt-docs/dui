```ts
import { configure, presets } from '@bdocs/dui'
```

Ocho paletas curadas vienen incluidas en `@bdocs/dui` para tematizar cada widget — `badge`, `modal`, `tabs`, `box`, `section`, `spinner`, `progress`, `markdown`, `kbd` — con **una línea** de código:

```ts
configure({ theme: presets.dracula })
```

Un preset es un `Partial<DuiTheme>` (ver [`DuiTheme`](./theme)). Los slots que no define caen a los valores por defecto integrados, así que cada paleta se enfoca en las superficies de alto impacto en lugar de escribir cada hoja.

```ts
import { presets, type PresetName } from '@bdocs/dui'

const theme: PresetName = 'catppuccin'
configure({ theme: presets[theme] })
```

La unión `PresetName` hace que las paletas mal escritas fallen en tiempo de compilación — un typo como `presets.draclua` lo detecta `tsc --noEmit` antes de llegar a CI.

El registro se exporta como `Readonly<Record<PresetName, DuiThemePreset>>` y el objeto subyacente está `Object.freeze`d para que una mutación accidental de un llamador no se filtre entre consumidores.

## Cómo funciona la cascada

Los presets usan el mismo pipeline `configure({ theme })` que un `DuiTheme` a mano. Tres capas componen, en orden de prioridad:

1. **Sobrescrituras del usuario** — lo que pases inline gana:
   ```ts
   configure({
     theme: {
       ...presets.dracula,
       error: '#ff00ff', // fija este único slot
     },
   })
   ```
2. **Paleta del preset** — el valor en `presets.X.<slot>`.
3. **Valores por defecto** — el `map[slot]` interno de `resolveColor` (`packages/dui/src/theme.ts`), aplicado al final.

También aplica el fallback por slot: si `box.title` no está en un preset pero el `title` global sí, `box.title` reutiliza `title`.

## Cascada en la salida de los widgets

Una vez aplicada, cada widget usa la paleta vía `resolveColor`:

```ts
configure({ theme: presets.dracula })
const out = badge({ label: 'PASS', status: 'success' })
// out contiene `\u001b[48;2;80;250;123m` (Dracula success bg)
```

El SGR RGB de 24 bits abre con `\u001b[48;2;<r>;<g>;<b>m`, así que un consumidor puede buscar el hex del preset inspeccionando la pintura cruda.

## Forzar salida de texto plano

`plain: true` es **ortogonal** a los presets. Pásalo junto a una paleta para mantener la introspección del tema mientras colapsas cada render al fallback de texto `prefix:` — útil para lectores de pantalla en Linux, scrapers de logs de CI o cualquier host sin render ANSI:

```ts
configure({ theme: presets.dracula, plain: true })
```

La paleta Dracula se sigue resolviendo en el mapa de slots (así `getConfig().theme` muestra la paleta prevista), pero cada widget emite salida solo-texto. Ver la referencia completa de accesibilidad en [Accessibility](/docs/next/overview/accessibility).

## Añadir tu propio preset

Añade una nueva entrada a `packages/dui/src/presets.ts`:

```ts
import type { DuiThemePreset } from '@bdocs/dui'

const myPreset: DuiThemePreset = {
  success: '#...tu hex...',
  error: '#...tu hex...',
  /* ... */
}

Object.assign(presets, { myPreset })
```

La receta habitual: 1) añade `"myPreset"` a `PresetName`, 2) añade la constante + entrada en el literal `Readonly<Record>` para que el cambio esté type-checked desde ambos lados.

Una paleta nueva usa automáticamente el mismo pipeline `markRawTheme` / `resolveColor` / `configure`. Sin paso de registro separado.

## Sobrescribir un solo slot

```ts
// sobrescribe el color success SOLO, manteniendo el resto de Gruvbox
configure({
  theme: {
    ...presets.gruvbox,
    success: '#b4dc54',
  },
})
```

O vía el argumento `colors:` por llamada en el propio widget:

```ts
badge({ label: 'DRAFT', status: 'neutral', colors: { bg: '#bd93f9' } })
```
